# Novel Reader 顶尖体验版本：手工验证计划

本计划用于验证安全加固、数据迁移、用户匿名化、可信代理、同源写入、认证抗压、幂等、Engagement、原创富文本编辑器、图片与付费边界，以及两个 UI 修复。

> 必须先在生产数据库副本和隔离环境执行。数据库备份、恢复演练和阻断项通过之前，不得直接替换生产数据。

# 一、15 分钟发布阻断冒烟测试

以下任一项失败，立即停止上线。

1. 在数据库副本上执行：

   ```bash
   npm run db:backup -- ./backups/pre-upgrade.sqlite
   npm run db:verify -- ./backups/pre-upgrade.sqlite
   ```

   预期：备份存在，`quickCheck` 只有 `ok`，`foreignKeyViolations` 为空。

2. 启动新版本，访问：

   ```text
   GET /api/live
   GET /api/ready
   GET /api/version
   ```

   预期：`live` 为 200；`ready.ok=true`；版本 SHA 与部署提交一致。

3. 登录普通账号，进入原创新建页，输入标题与三段正文，停顿 2 秒。

   预期：显示“已保存”；刷新后正文仍在；关闭标签页重新打开仍可恢复。

4. 发布一篇免费文章。

   预期：只生成一篇；默认价格是 0；正式页能正常阅读；刷新不会重复扣费或重复发布。

5. 新建付费文章，插入一次付费分界，分界前后各输入正文后发布。

   预期：未购买账号只收到公开内容；HTML、RSC、目录和图片地址中均无付费内容。

6. 快速双击商城购买按钮，或用开发者工具重复同一个 `mutationId` 10 次。

   预期：只生成一笔订单、只扣一次余额、只发放一次交付物。

7. 后台选择一个有原创、评论、订单和流水的测试作者，执行“停用并匿名化”。

   预期：作者无法登录；文章、评论、购买关系、订单与流水仍存在。

8. 将文章页链接放到列表中，只触发 hover/prefetch，不让正文可见。

   预期：浏览数、阅读历史和树林访问数不增加。

9. 模拟跨域或同站不同子域调用写 API，缺少 `X-Novel-Mutation: 1`。

   预期：403，且数据库无写入。

10. 打开小说末尾“上一篇 / 下一篇”区域。

    预期：标题根据实际文字自然换行，不再强制两行对齐；源码中的换行或多余空格不会造成错误标题断行。

11. 打开用户工作台中的动态、消息、集市、文章页面。

    预期：页面标题左侧图标保持中性灰，和“设置”图标一致，不跟随主题强调色变色。

# 二、数据库迁移与恢复

## 2.1 升级前备份

对真实生产数据库副本执行：

```bash
npm run db:backup -- ./backups/novels-before-upgrade.sqlite
sha256sum ./backups/novels-before-upgrade.sqlite
npm run db:verify -- ./backups/novels-before-upgrade.sqlite
```

确认：

- 备份文件不是 0 字节。
- SHA-256 已记录。
- `quickCheck=ok`。
- 外键违规为 0。
- 备份能被 SQLite 打开并查询核心表。

## 2.2 访问控制迁移对账

升级前后分别统计：

```sql
SELECT COUNT(*) FROM content_access_rules;
SELECT COUNT(*) FROM content_access_policies;
SELECT target_type, scope, enabled, COUNT(*)
FROM content_access_rules
GROUP BY target_type, scope, enabled
ORDER BY 1, 2, 3;
```

重点验证：

- IP、CIDR、国家、爬虫规则均保留。
- 旧 `media` 作用域等价扩展为 video/audio/file，不静默丢失。
- disabled 规则仍保持 disabled。
- 过期时间、原因、受众与来源语义保留。
- 任意无法转换的坏数据会阻止升级，而不是跳过。

## 2.3 完整性

升级后执行：

```sql
PRAGMA quick_check;
PRAGMA foreign_key_check;
SELECT * FROM schema_migrations ORDER BY version;
```

预期：

- `quick_check` 返回 `ok`。
- `foreign_key_check` 零行。
- `schema_migrations` 包含本版本迁移记录。

## 2.4 回滚演练

1. 停止新版本。
2. 保存升级失败现场数据库。
3. 用 `novels-before-upgrade.sqlite` 恢复。
4. 启动旧版本。
5. 验证登录、书库、原创与订单读取。

回滚必须实际演练一次，不能只确认备份文件存在。

# 四、可信代理与客户端身份

## 4.1 none 模式

```env
TRUST_PROXY_MODE=none
```

分别伪造：

```text
CF-Connecting-IP: 127.0.0.1
X-Forwarded-For: 127.0.0.1
X-Real-IP: 127.0.0.1
CF-IPCountry: CN
```

预期：这些头不会成为可信客户端身份，也不能绕过后台 IP 白名单、注册限额或内容访问规则。

## 4.2 signed 模式

```env
TRUST_PROXY_MODE=signed
TRUST_PROXY_SECRET=<至少 32 字符随机值>
TRUST_PROXY_IP_HEADER=x-novel-client-ip
TRUST_PROXY_COUNTRY_HEADER=x-novel-country
```

反向代理必须先删除外部同名头，再重新写入真实值和 `X-Novel-Proxy-Secret`。

测试：

- 正确 secret + 合法单一 IP：被信任。
- 错误 secret：身份为 unknown。
- 空 secret：readiness 失败。
- 多值 IP、换行注入、非法 IPv6：拒绝。
- 用户自己附加 `X-Forwarded-For`：不能覆盖代理写入值。

## 4.3 Cloudflare 模式

```env
TRUST_PROXY_MODE=cloudflare
```

确认源站端口只能由 Cloudflare 或内部代理访问。然后验证：

- 经 Cloudflare 请求能读取真实 IP / 国家。
- 绕过 Cloudflare 直连源站不可达。
- 伪造 Cloudflare 头不能通过另一条公开源站路径生效。

# 五、统一同源写入保护

对以下接口至少各测试一个 POST/PUT/PATCH/DELETE：

```text
账户偏好和阅读进度
小说收藏、树林、推荐、解锁
原创草稿、发布、Engagement、图片
媒体收藏、反馈、树林、推荐、解锁
举报和分析事件
```

请求矩阵：

| 场景 | 预期 |
|---|---|
| same-origin + 正确 Origin + `X-Novel-Mutation: 1` | 正常执行 |
| 外部 Origin | 403 |
| 同一主域不同子域 | 403 |
| `Sec-Fetch-Site: same-site` | 403 |
| 缺少自定义 mutation 头 | 403 |
| 非法 JSON | 400/415 |
| GET / HEAD | 不产生状态变更 |

观察数据库，所有拒绝请求均不能产生半写入。

# 六、普通用户认证与抗压

## 6.1 正常流程

- 新密码少于 10 字符：明确拒绝。
- 10–256 字符长口令：可注册、登录和修改。
- 旧 PBKDF2 测试账号首次成功登录后，密码哈希升级为 `scrypt:v1:`。
- 错误用户名与错误密码的提示完全一致。
- pending / disabled 账号规则保持正确。

## 6.2 三维限流

验证：

- 同 IP 不同用户名达到 IP 限制。
- 不同 IP 同用户名达到用户名限制。
- 同 IP 同用户名达到组合限制。
- 达到限制返回合理 `Retry-After` 或用户提示。
- 成功登录清除该组合的失败状态。

## 6.3 事件循环抗压

在测试环境并发发出 100 个错误登录，同时每 100ms 请求一次 `/api/live` 与首页。

记录：

```text
错误登录总耗时：
/api/live p50 / p95 / max：
首页 p50 / p95 / max：
CPU 峰值：
内存峰值：
```

通过标准：健康检查持续响应，页面无长时间假死，密码验证并发保持有界。

# 七、高价值操作幂等

每个场景都复用同一个 mutation ID 并发发送 10 次：

1. 商城购买。
2. 原创草稿发布。
3. 已发布文章再次提交同一发布请求。
4. 网络超时后客户端重试同一请求。

验证：

- 业务记录只产生一次。
- 余额只变化一次。
- 流水只产生一次。
- 卡密只消耗一条。
- 返回的业务 ID / slug / orderNo 一致。
- 同一 mutation ID 用于不同用户或不同 operation 时被拒绝。

另行测试新 mutation ID：应被视为新的明确操作。

# 八、Engagement 与预取纯度

对小说、原创、视频、音频和文件分别执行：

1. 只 hover 链接触发预取。
2. 发起 RSC 预取请求。
3. 调用 metadata / HEAD。
4. 在后台标签页打开页面。
5. 主体可见不足 30%。
6. 主体可见超过 30%，但少于 1.5 秒。
7. 主体可见超过 30%，持续 1.5 秒以上。
8. 复用相同 event ID 100 次。
9. 同一访问者在 30 分钟窗口内生成不同 event ID。
10. 超过窗口后再次真实访问。

预期：

- 1–6 不计数。
- 7 计数一次。
- 8 不重复。
- 9 不重复刷量。
- 10 按产品窗口规则再次计数。
- 原创 `detail_view` 与 `read_open` 分离。
- 媒体详情浏览不等于播放器实际开始播放。

# 九、原创编辑器基础体验

## 9.1 首次进入

- `/original/new` 先创建服务端草稿，再进入专用工作区。
- 普通站点导航、面包屑和表单卡片不占写作空间。
- 新文章默认免费，价格为 0。
- 标题和正文位于自然文档流。
- 桌面工具栏、底部状态栏几何稳定。
- 手机仅保留返回、保存状态、发布和键盘上方格式栏。

## 9.2 格式能力

逐项验证：

```text
H2 / H3
加粗 / 斜体 / 下划线 / 删除线
有序 / 无序列表
引用
代码块 / 行内代码
分隔线
链接
图片
付费分界
撤销 / 重做
Markdown 快捷输入与旧文章导入
```

要求：

- H1 只属于文章标题，正文不产生第二个 H1。
- H2/H3 目录层级正确。
- 标题节点 ID 在改名、前方插入标题和排序后仍保持稳定。
- 代码块保留空格、换行和全角字符。
- 链接 URL 保存前后不被 NFKC 改写。
- 外部危险协议不能成为可点击链接。

## 9.3 中文输入法

在 iOS、Android、macOS 和 Windows 中文输入法中验证：

- 拼音候选尚未确认时不会触发结构转换或自动格式。
- 连续输入不卡顿、不跳光标。
- 组合输入期间不会保存破碎中间态。
- 候选确认后 0.9–2 秒内显示已保存。
- 撤销一次只撤销用户可理解的一步。

## 9.4 粘贴

分别粘贴：

- Word 富文本。
- 网页段落与链接。
- 纯文本。
- Markdown。
- 代码。
- 截图和剪贴板图片。

确认无脚本、事件属性或任意 HTML 被保留；排版不会生成不可删除的空块。

# 十、草稿与冲突

## 10.1 自动保存

- 输入停止约 900ms 后服务端保存。
- 持续输入时最多约 5 秒必须保存一次。
- 300–500ms 内写入 IndexedDB 本地副本。
- 保存状态依次为未保存、正在保存、已保存。
- 自动保存不扣发布费或编辑费。

## 10.2 网络故障

1. 开始写作。
2. 断网。
3. 继续输入至少 1,000 字。
4. 刷新或关闭标签页。
5. 恢复网络并重新进入。

预期：显示本地恢复提示，内容完整；恢复后安全同步到服务端。

## 10.3 服务端错误

人为让 PATCH 返回 500 或让数据库只读。

预期：

- 明确显示保存失败。
- 当前文本仍在编辑器中。
- 本机恢复副本存在。
- 点击重试有效。
- 不能在草稿未保存时假装发布成功。

## 10.4 两标签页冲突

1. 同一草稿打开 A、B 两个标签页。
2. A 修改并保存。
3. B 基于旧 revision 修改并保存。

预期：B 收到 409，并显示选择：使用服务器版本或保留当前内容；不能静默覆盖。

# 十一、付费分界与付费数据边界

## 11.1 编辑规则

- 免费文章不能保留付费分界。
- 付费文章必须且只能有一个分界。
- 分界前后必须都有有效正文。
- Backspace 不会无提示破坏分界。
- 删除分界需要确认。
- 撤销/重做跨分界正确。
- 分界前后的标题和图片被正确归类。

## 11.2 未授权响应检查

使用未登录和未购买账号保存完整响应：

```bash
curl -sS -D headers.txt https://example.com/original/<slug> -o article.html
```

同时检查浏览器 Network 中的 RSC payload。

必须满足：

- 付费正文关键句在 HTML 中出现 0 次。
- 付费标题出现 0 次。
- 付费图片真实 URL / asset ID 出现 0 次。
- 公开目录末尾最多显示不泄漏标题的锁定占位。
- 不是用 CSS blur、display:none 或前端条件渲染隐藏付费正文。

## 11.3 解锁后

- 支付一次后永久可读。
- 刷新、换设备登录后仍可读。
- 解锁后正文插入位置稳定，不突然跳到顶部。
- 付费图片可以加载，公共缓存头与私有缓存头正确区分。

# 十二、原创图片

准备：JPEG、PNG、WebP、AVIF、带 EXIF 方向照片、透明图、动画图、伪装扩展名、损坏文件、超 10MB 文件、超 40MP 图片。

验证：

- 合法图片可通过选择、拖放和粘贴上传。
- 服务端实际解码、纠正方向、限制尺寸并重编码 WebP。
- EXIF 和隐藏元数据被移除。
- 损坏文件、图片炸弹和超限文件明确拒绝。
- 图片替代文本有输入提示。
- `width`、`height` 或等价 aspect-ratio 存在，正文加载无 CLS。
- 草稿图片只有作者或管理员可访问。
- 公开区图片可长期缓存。
- 付费区图片对未购买者返回 404/拒绝。
- 图片真实路径不能通过 `../` 或符号链接逃逸。

# 十四、原创正式阅读页

## 14.1 信息层级

确认首屏优先显示标题、作者和正文，不被小说章节操作抢占。

- 正文版心桌面约 700–704px。
- 桌面正文约 17px / 1.8。
- 手机约 17px / 1.82。
- 普通段落使用统一段距，不保留任意源码空行放大效果。
- 普通段落 `white-space: normal`。
- 代码块单独保留空格。
- 原创页不显示小说式上一篇/下一篇主导航。
- 图片说明、引用、列表、代码和分隔线样式一致。

## 14.2 目录

- 至少两个 H2/H3 才显示目录入口。
- 大屏目录粘性显示，中屏/手机通过面板打开。
- 当前章节高亮并使用 `aria-current`。
- 点击目录尊重减少动画偏好。
- 修改标题文字不会破坏旧 anchor ID。
- 未解锁目录绝不泄漏付费标题。

## 14.3 阅读位置

当前版本至少验证比例恢复不出现明显跳转；后续稳定 block anchor 可进一步精调。

测试：

- 修改字号。
- 横竖屏切换。
- 图片加载前后。
- 简繁切换。
- 关闭再进入。

记录实际漂移到相邻哪一段。

# 十六、邮箱验证、头像与 HTTP 头

## 16.1 邮箱验证

- 邮件扫描器或 curl 只 GET 验证 URL：账号仍 pending。
- 用户打开页面后点击“确认验证邮箱”：POST 消费 token。
- token 只能成功一次。
- 过期、篡改和已消费 token 返回统一提示。

## 16.2 头像

- 上传合法图片后最终文件为受控 WebP。
- 像素尺寸不超过 512×512。
- EXIF 不存在。
- 损坏、伪造、巨图和异常编码被拒绝。
- 旧头像在数据库更新成功后才删除。

## 16.3 头部

检查：

```text
X-Content-Type-Options
X-Frame-Options / frame-ancestors
Referrer-Policy
Permissions-Policy
Content-Security-Policy-Report-Only
Strict-Transport-Security（仅已确认全子域 HTTPS 时启用）
```

先观察 CSP report-only 报告，确认没有必要资源被意外阻止，再讨论切换为强制 CSP。

# 二十一、停止上线条件

以下任一项出现，停止上线并保留现场：

- 访问控制迁移前后规则丢失或语义变化。
- `quick_check` 非 `ok` 或有外键违规。
- 匿名化导致文章、评论、订单、购买或流水消失。
- 未授权响应中出现任何付费正文、付费标题或付费图片地址。
- 同一 mutation ID 重复扣费、发货或发布。
- 跨站 / 同站不同子域写请求成功。
- 伪造代理头绕过安全规则。
- 服务端保存失败后草稿无法恢复。
- 两标签页静默覆盖。
- `npm ci`、类型检查、单元测试或生产构建失败。
- 部署 `/api/version.commit` 与 GitHub / 镜像 SHA 不一致。
- 新版本出现持续 `SQLITE_BUSY`、Node 假死或明显数据损坏。
